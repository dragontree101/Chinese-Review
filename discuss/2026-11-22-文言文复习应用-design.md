# 初中文言文生词复习应用 — 设计文档

日期：2026-11-22
状态：待用户确认

## 一、意图与背景

把现有仓库（一份 `default.json` 数据：1333 条文言实词记录，覆盖 299 个字，每条含「字 / 含义 / 例句（带出处）」）改造为一个 **Node.js Web 应用**，帮助初中生学习和复习文言文生词。学生通过网页答题复习，系统记录每道题的作答情况，统计正确率、错误率、不认识率，并按多种规则出题强化薄弱点。

## 二、目标 / 非目标 / 反目标

**目标**
1. 复习答题：选择题 + 填空题两种题型，可点「不知道」
2. 多种出题规则：按年级、按拼音首字母、关键字筛选、按频率、按错误率优先
3. 多维度统计：总体正确率/错误率/不知道率，按字、按年级、按出处，近 7 天趋势
4. 数据管理页：逐条查看、搜索、编辑（补填课文/年级/翻译，后期人工修正）
5. 数据初稿自动生成：出处自动解析、白话翻译由 AI 生成初稿、年级课文按初中篇目表推断

**非目标**
- 不做多用户/账号系统（单学生使用）
- 不做移动端 App，只做响应式网页
- 不做发音、笔顺等扩展功能

**反目标（出现即为失败）**
- 统计数据不准（如答错被计入正确）
- 数据编辑后统计或出题行为不一致

## 三、约束

- 技术栈（用户指定）：Next.js 15.4 + React 19 + Tailwind CSS v4 + TypeScript + SQLite
- 硬性指标：单个代码文件 ≤ 800 行；每层文件夹文件数尽量 ≤ 20
- Run & Debug 一律通过 `scripts/` 目录下 .sh 脚本，日志输出到 `logs/`
- 严格 TypeScript，不用 any；根目录保持简洁
- SQLite 数据库文件：`data/app.db`

## 五、数据模型

### words 表（词条）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 原始 id |
| char | TEXT | 字（如「哀」） |
| meaning | TEXT | 含义（如「悲伤，悲哀」） |
| sentence | TEXT | 例句原文（含出处） |
| source | TEXT | 出处，导入时从 sentence 中用 `《…》` 正则解析 |
| translation | TEXT | 例句白话翻译（AI 生成初稿，可空、可编辑） |
| lesson | TEXT | 课文（按初中篇目表推断初稿，可空、可编辑） |
| grade | TEXT | 年级（七年级/八年级/九年级，推断不出则空，可编辑） |
| created_at / updated_at | TEXT | 时间戳 |

**「相同含义的句子」**：不落库，运行时按 `char + meaning` 分组查询推导（同字同含义的其他例句），显示在卡片详情里。理由：落库后一旦用户编辑含义就会与分组脱节，产生数据不一致。

**频率**：不落库，运行时按该 `char` 的词条总数计算（一词多义条目多 = 高频）。

### review_logs 表（作答记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | |
| word_id | INTEGER FK→words | |
| mode | TEXT | 'choice' \| 'fill' |
| result | TEXT | 'correct' \| 'wrong' \| 'unknown' |
| user_answer | TEXT | 学生选的/输入的内容 |
| created_at | TEXT | 时间 |

### 填空题判定规则

含义字段常为顿号分隔的多个近义词（如「悲伤，悲哀，哀叹，哀悼」）。判定逻辑：
1. 学生输入去掉空白与标点
2. 与 meaning 按分隔符拆出的每个关键词做「包含」匹配，命中任一关键词即 correct
3. 未命中判 wrong，但显示正确答案，并提供「判我对」按钮，可覆盖为 correct（覆盖也记一条日志，统计以日志为准，原始作答保留）

## 六、出题规则

`GET /api/quiz?rule=xxx&value=yyy&count=10` 返回一批题目（服务端生成，含干扰项）。

| 规则 | 参数 | 逻辑 |
|------|------|------|
| 随机（默认） | random | 全库随机 |
| 按年级 | grade | grade = 七/八/九年级 的词条随机 |
| 按首字母 | initial | char 的拼音首字母 = 指定字母 |
| 关键字 | keyword | char 或 meaning 包含关键字 |
| 按频率 | frequency | 按 char 的词条数降序取高频字 |
| 错误率优先 | weakness | 最近作答中 wrong/unknown 占比高的词优先，无记录的新词次之 |

拼音首字母：使用 `pinyin-pro` 库（轻量、纯 JS、无需字典文件）。

选择题干扰项：优先取**同字的其他含义**（最有迷惑性），不足 3 个再从其他字的含义中随机补足。

## 七、页面结构

```
/          首页：数据概览 + 三个入口（复习 / 统计 / 数据管理）
/review    复习页：选题单（规则+题型+数量）→ 答题卡（正面：字+例句）→ 作答 → 即时反馈 → 下一题 → 小结
/stats     统计页：总体正确率/错误率/不知道率大数字；按字、按年级、按出处排行；7 天趋势折线
/manage    数据管理页：分页列表 + 搜索（字/含义/例句/出处/课文/年级）；行内编辑 translation/lesson/grade/source/meaning
```

## 八、API 设计（Route Handlers）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/words | 分页列表 + 搜索 |
| PATCH | /api/words/:id | 编辑词条字段 |
| GET | /api/quiz | 按规则出题（见第六节） |
| POST | /api/review | 提交作答（写入 review_logs） |
| GET | /api/stats | 汇总统计（总体/分维度/趋势） |
| GET | /api/stats/words | 按字排行 |

## 九、数据导入与初稿生成

`scripts/init-db.sh` → 执行 `src/scripts/import.ts`（tsx 运行）：

1. 建表；读取 `default.json` 全量插入
2. 正则解析 sentence 中的 `《…》` 写入 source
3. 按**初中篇目映射表**（内置一份《××》→ {grade, lesson} 映射，覆盖统编初中语文教材文言篇目，如《论语》《桃花源记》《木兰诗》《曹刿论战》《出师表》等约 40 篇）推断 grade/lesson；不在表中的留空
4. 读取 `data/translations.json`（开发阶段由 AI 逐句生成的白话翻译初稿，1333 条）合并写入 translation；缺的留空

**关于翻译初稿**：由 AI 分批生成，逐条人工抽查核对成本过高，以「初稿」定位，页面上随时可改。生成时保留出处上下文，翻译以句为单位而非词条为单位（同一句出现在多条记录时翻译一致）。

## 十三、评审补充决策（2026-11-22，builder check 后确认）

数据核查发现：1333 条中以高中篇目为主（廉颇蔺相如列传 74、促织 49、鸿门宴 48、过秦论 47 等），初中篇目占少数。

1. **年级档位（用户已确认）**：`grade` 取值为 `七年级|八年级|九年级|拓展|null`。初中篇目映射表命中的按学段填；高中篇目填「拓展」；无出处的留空。数据全部保留，「按年级出题」包含拓展档。
2. **keyword 字段入库**：它承载多音字读音（如 `辟(bì)`）与词形变体，随导入存入 words 表并在卡片上展示；「按首字母」规则优先用 keyword 括号中的读音推断首字母，pinyin-pro 兜底。
3. **出处解析**：优先取**句末括号内**的 `《…》`（避免误抓正文书名号，如《诗三百》）；标注「（成语）」的条目 source 记为「成语」；完全无出处留空。
4. **填空判定**：双向包含（输入含关键词 或 关键词含输入 均算对），匹配前剥离「同X」「为动」「使动」「意动」等注释成分。
5. **「判我对」**：就地更新原作答记录的 result 为 correct 并打 `overridden=1` 标记，**不追加新日志**（保证一次作答一条日志，分母不膨胀）。
6. **翻译初稿**：开发期由 AI 离线分批生成 `data/translations.json`（键=唯一例句），不引入 LLM API 依赖。
7. **错误率优先窗口**：统计全部历史作答。
