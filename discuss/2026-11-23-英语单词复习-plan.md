# 英语单词复习模块 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有文言文复习应用中新增英语单词复习板块：submodule 引入词库 → 导入初中+高中词 → 出题/作答/统计全链路。

**Architecture:** 新增 `e_words`/`e_review_logs` 两张独立表与 `src/lib/english/` 逻辑层（解析/出题/统计），UI 按现有组件模式在 `src/components/english/` 复刻一套，页面挂在 `/english/*`，顶部导航加科目切换。现有文言文代码除 `db.ts`（加表）与 `SessionSummary`（加链接参数）外不动。

**Tech Stack:** Next.js 15.4 / React 19 / TypeScript / better-sqlite3 / vitest / Tailwind v4

**Spec:** `discuss/2026-11-23-英语单词复习-design.md`（数据侦察结论与决策以该文档为准）

## Global Constraints

- 所有注释、文档、UI 文案使用简体中文；代码标识符用英文
- TypeScript 文件 ≤ 800 行；每层文件夹 ≤ 20 个文件
- 严禁 commonjs；数据结构强类型，禁止 any / 未结构化 dict
- 运行/调试一律走 `scripts/` 下的 .sh；测试用 `bash scripts/test.sh [文件]`（支持传 vitest 目标参数）
- 端口 3888；日志输出到 `logs/`
- 测试约定照 `src/lib/__tests__/quiz.test.ts` 的 seedDb 模式（`:memory:` + createSchema + 逐条 INSERT）

## Review Focus

以下输入场景规格未显式覆盖，按此预期行为，各归属任务的测试已列入对应步骤：

1. **单词释义为空**（数据文件变化或手改库后 choice 无正确项文本）→ `mergeWord` 对释义为空的词返回 null 不入库；`pickWords` 只返回 `meanings.length > 0` 的词 —— Task 3 / Task 5 测试
2. **导入幂等性**（重复执行 import 后行数翻倍/学段漂移都不可接受）→ 同一文件连续两次导入，行数与学段分布不变 —— Task 4 验证步骤
3. **拼写判定的大小写与空白**（`"Apple "`、`"APPLE"` 必须判对）→ `judgeEnglishFill` trim + 忽略大小写 —— Task 5 测试
4. **选择题干扰项不足**（词库极小或释义全相同时 options 仍不报错、不含重复项、始终含正确答案）→ `pickDistractors` 极端用例 —— Task 5 测试
5. **submodule 未初始化时执行导入**（clone 后直接 reset-db）→ 报错并提示 `git submodule update --init third_party/english-vocabulary` —— Task 4 验证步骤

### Task 3: 词库行解析与合并（lib/english/parse.ts）

**Files:**
- Create: `src/lib/english/parse.ts`
- Test: `src/lib/english/__tests__/parse.test.ts`

**Interfaces:**
- Consumes: Task 2 的 `EnglishLevel`、`Meaning`、`SentencePair`、`Phrase`
- Produces:
  - `RawVocabEntry { bookId: string; headWord: string; usphone: string | null; ukphone: string | null; trans: Array<{ pos: string; tranCn: string }>; sentences: Array<{ sContent: string; sCn: string }>; phrases: Array<{ pContent: string; pCn: string }> }`
  - `parseLine(line: string): RawVocabEntry | null` —— 解析 jsonl 一行，取 `bookId`、`headWord`、`content.word.content` 内字段；结构缺失返回 null
  - `ParsedWord { word; level; usphone: string | null; ukphone: string | null; meanings: Meaning[]; sentences: SentencePair[]; phrases: Phrase[] }`
  - `mergeWord(headWord: string, entries: RawVocabEntry[]): ParsedWord | null` —— 合并同一单词的多条来源：
    - level：任一 `bookId` 以 `ChuZhong` 开头 → `初中`，否则 `高中`
    - meanings：`{ pos, tran: tranCn.trim() }`，按 `pos|tran` 去重，保持首次出现顺序，tran 为空的丢弃
    - sentences/phrases：trim 后按 en 去重，保持首次出现顺序
    - usphone/ukphone：取第一个非空值
    - 合并后 meanings 为空 → 返回 null（Review Focus #1）

// 2. parseLine 对空行、坏 JSON、缺 content 返回 null
// 3. levelFromBookIds：含 ChuZhong_2 → 初中；仅 GaoZhong_* → 高中
// 4. mergeWord 跨书合并：释义并集去重、例句按 en 去重、音标取非空
// 5. mergeWord 全部来源释义为空 → null
// 6. 顺序稳定性：同一输入两次 mergeWord 输出 JSON 相同（导入幂等的基础）

### Task 5: 出题与判定逻辑（lib/english/quiz.ts）

**Files:**
- Create: `src/lib/english/quiz.ts`
- Test: `src/lib/english/__tests__/quiz.test.ts`

**Interfaces:**
- Consumes: Task 2 类型（EnglishWord/EQuizRule）、Task 2 schema
- Produces:
  - `formatMeanings(meanings: Meaning[]): string` —— `pos + ". " + tran` 用「；」连接，pos 为空时只输出 tran
  - `pickWords(db: Database, rule: EQuizRule, value: string, count: number): EnglishWord[]` —— 先过滤 `meanings.length > 0`（Review Focus #1）；`random` 全库洗牌取前 count；`level` 过滤 `level === value`；`initial` 取 `word[0].toUpperCase() === value.trim().toUpperCase()`；`weakness` 照 `src/lib/quiz.ts` 的 weakness 模式（按 e_review_logs 错误率降序 + 未作答词洗牌补足）
  - `pickDistractors(all: EnglishWord[], target: EnglishWord, n = 3): string[]` —— 候选为其他词的 `formatMeanings`，与正确答案及已选项去重，不足时允许少于 n（Review Focus #4）
  - `buildChoiceQuestion(word, distractors): { word, options, answer }` —— options 为洗牌后的 `[formatMeanings(word.meanings), ...distractors]`，answer 为正确项文本
  - `judgeEnglishFill(word: EnglishWord, input: string): boolean` —— `input.trim().toLowerCase() === word.word.toLowerCase()`（Review Focus #3）
