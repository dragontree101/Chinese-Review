# 文言文错误统计到「词条/句子」粒度 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 错误统计从「按字」细化到「按词条（字的一个含义 + 一条例句）」：统计页新增可点击的「错误句子排行」，点击查看词条完整详情与错误摘要；按字弹窗内每条词条标注错误次数。

**Architecture:** `review_logs` 已按 `wordId` 记录每次作答，句子随词条存储，**不改表结构、不改记录写入**，纯读侧扩展：stats lib 新增两个查询函数 → 两个 API 返回新维度 → 统计页新表 + 新弹窗 + CharDetailDialog 增强。

**Tech Stack:** Next.js 15.4、React 19、TypeScript strict、better-sqlite3、vitest

**Spec:** 会话中确认的短设计（2026-11-28）。参照实现：`src/lib/english/stats.ts:getWrongWords`（排序口径）、`EnglishStatTables/EnglishWordDetailDialog`（交互模式）、`src/lib/stats.ts:aggregate`（聚合 SQL 风格）。

## Global Constraints

- TypeScript strict、禁 any；运行/测试一律走 `scripts/*.sh`；UI 文案简体中文。
- 排序口径与英语模块一致：`HAVING wrong + unknown > 0`，`ORDER BY (wrong + unknown) DESC, answered DESC`，默认 limit 20。
- 不改 `review_logs` 表结构与写入逻辑；不改现有 `byChar/byGrade/bySource/trend` 口径。
- 「错误句子排行」每行携带词条信息（wordId/char/meaning/sentence 预览），sentence 预览超 18 字截断加 `…`（截断属展示细节，lib 返回完整句子，截断在 UI 做——裁定：lib 不截断，保持数据层纯净）。

## Review Focus

1. **无作答记录的词条也要出现在按字弹窗中**（计数为 0，不丢失）→ `getWordErrorsByChar` 必须用 LEFT JOIN，测试断言零作答词条在列且计数为 0。
2. **全对词条不进「错误句子排行」**（HAVING 过滤）→ 测试断言只有 wrong/unknown > 0 的词条在列。
3. **排序稳定**：同错误次数按作答总数降序、再按 wordId 升序 → 测试用两个同错误次数的词条断言顺序。
4. **弹窗找不到词条时的兜底**：错误排行行来自日志，若词条随后被人工变更（本应用无删除入口，极端情形），弹窗显示排行行自带数据而非空白。

```ts
/** 错误词条排行行（按 wordId 聚合，含词条信息） */
export interface WordErrorRow {
  wordId: number;
  char: string;
  meaning: string;
  sentence: string;
  wrong: number;
  unknown: number;
  total: number;
}

/** 携带错误计数的词条（按字查询用） */
export type WordWithErrors = Word & { wrong: number; unknown: number; total: number };
```
