# 间隔重复（SRS）设计文档

- 日期：2026-11-28
- 状态：待评审
- 关联：[文言文复习应用设计](2026-11-22-文言文复习应用-design.md)、[英语单词复习设计](2026-11-23-英语单词复习-design.md)

## 一、意图与背景

当前的复习出题是「静态题池」：`weakness` 规则按累计错误率排序，不看时间维度，复习节奏完全靠孩子和家长自己安排。本设计引入**间隔重复调度**，让每个词根据作答历史自动决定「什么时候该再出现」，实现从「随机刷题」到「科学复习」的升级，同时把词库分成「未学 / 学习中 / 已毕业」三桶，让孩子和家长直观看到进度。

## 二、目标 / 非目标 / 反目标

**目标**

1. 每个词条有自动演进的复习等级与到期时间，答对升级、答错归零。
2. 新增「智能复习」出题规则：到期词优先全出，不足用新词补齐。
3. 文言文与英语两个模块共用同一套 SRS 逻辑。
4. 统计与首页展示掌握度分桶（未学 / 学习中 / 已毕业）。
5. 从现有 `review_logs` / `e_review_logs` 实时推导状态，**不新增调度表**。

**非目标**

- 不做 SM-2 / ease 系数等自适应参数（本轮采用固定阶梯）。
- 不改选择题/填空题的题型与判定逻辑。
- 不做每日打卡、游戏化激励（另立方案）。
- 不做跨设备同步（仍是本地单机应用）。

**反目标（做了即失败）**

- 破坏现有 6+4 种出题规则的可用性（它们服务于按年级预习等定向练习场景，必须保留）。
- 让统计分母膨胀或与「判我对」机制冲突。
- 需要数据迁移才能上线的方案（老日志必须直接可用）。

## 三、约束

- 单机 SQLite（WAL），数据量 ≤ 4000 词 + 数万条日志，实时推导性能可接受（≤ 数十毫秒量级）。
- 两个日志表结构完全一致（`wordId / mode / result / userAnswer / overridden / createdAt`），共用逻辑可行。
- 「判我对」就地覆盖 `result='correct'` 并置 `overridden=1`，推导逻辑必须以覆盖后的最终结果为准。
- 时间基准：本地时区的自然日（「今天」），不用 UTC 日期切分。

## 四、方案取舍（已评审选定）

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 固定阶梯（Leitner 式） | 规则可解释、无参数可调坏、行为可预测 | 不区分难词与偶然失误 | **✅ 选定** |
| SM-2（Anki 同款） | 自适应、精细 | 参数黑箱、ease 可能卡死、不适合儿童场景 | 弃 |
| 简化 SM-2 | 折中 | 复杂度仍偏高 | 弃 |

**覆盖范围**：文言文 + 英语两个模块（用户选定）。
**每次复习的量**：到期全出（封顶 30），不足用新词补齐；孩子自主决定是否继续加练（用户选定）。

## 五、核心设计

### 5.1 阶梯定义

等级 `level: 0..6`，共 7 级；间隔表：

| level | 含义 | 升级后再现间隔 |
|-------|------|----------------|
| 0 | 刚答错 / 新词 | 次日到期 |
| 1 | 答对 1 次 | 1 天 |
| 2 | 连对 2 次 | 2 天 |
| 3 | 连对 3 次 | 4 天 |
| 4 | 连对 4 次 | 7 天 |
| 5 | 连对 5 次 | 15 天 |
| 6 | 毕业 | 不再出题 |

- **答对（correct，含被判我对覆盖）**：`level = min(level + 1, 6)`；到达 6 即毕业。
- **答错（wrong）或不知道（unknown）**：`level = 0`，**次日到期**（当日不再重出，已评审确认）。
- **到期时刻语义**：按本地自然日计算——`dueAt = 最后一次作答日 + 间隔天数` 的当天 00:00（本地时区）。晚上答对，第二天一整天都算到期，符合放学/睡前使用节奏。
- **mode（choice/fill）不区分**：同一阶梯。识别与主动回忆难度不同，留作后续精细化，本轮不做。
- **同一词条一天内多次作答**：以当天最后一次作答决定 level；当日会话内答错的词不再重复出现（去重靠出题队列）。
- **毕业无粘性（有意设计，已评审确认）**：已毕业的词在其他规则（随机等）下答错会归零重回循环——「不再出题」仅指智能复习不再主动推。状态是日志的纯函数，不为毕业词开例外。

### 5.2 状态推导（不落库）

新建 `src/lib/srs.ts`，输入该模块全部日志，输出 `Map<wordId, SrsState>`：

```ts
interface SrsState {
  level: number;        // 0..6
  graduated: boolean;   // level === 6
  dueAt: string;        // ISO 时间；毕业词为 null
  isNew: boolean;       // 从未作答
}
```

推导算法：按 `wordId` 聚合日志 → 按 `createdAt` 排序重放 → 答对升级、答错归零 → 由最后一次作答时间 + 间隔表得出 `dueAt`。`overridden=1` 的记录按其最终 `result` 参与重放（数据已就地更新，天然一致）。

哲学与现有「频率」「相同含义的句子」一致：**状态是日志的纯函数**，无同步问题、无迁移、无新表。4000 词 × 数万日志的单次重放在 better-sqlite3 下为毫秒级。

### 5.3 出题规则 `due`

`pickWords` 新增规则 `due`（智能复习）：

1. **到期词**：`dueAt ≤ now` 且未毕业的词，按「最久未到期优先」排序，封顶 30 个，全出。
2. **新词补齐**：到期不足时，用从未作答的词补齐（随机），补到「到期数 + 新词数 ≥ 10」即停（保证小节有足够体量）；无新词可补则到此为止。**英语模块补齐时不区分学段**（到期词同样不分学段全出；已评审确认，与文言文 `weakness` 全库补齐先例一致）。
3. **不引入未到期词**：孩子没练完也不产生「被迫复习还没到期的词」。

其余 6 种现有规则保持不变；智能复习在复习设置页置顶并默认选中。

### 5.4 API 变更

| 接口 | 变更 |
|------|------|
| `GET /api/quiz?rule=due` | 返回题目列表 + 会话元信息 `{ dueCount, newCount }` |
| `POST /api/review`（及 english 对应路由） | 响应在 `{ ok, result, logId }` 基础上增加 `srs: { level, graduated, nextIntervalDays }`——服务端权威返回作答后的 SRS 状态，前端不复制间隔表逻辑 |
| `GET /api/srs/progress`（新增，文言文与 english 各一份） | 返回 `{ unlearned, learning, graduated, byLevel: number[7] }` |

### 5.5 UI 变更

- **复习设置页**：新增「智能复习」卡片置顶（默认选中），展示「今日到期 N · 新词 M」；出题数量输入框在该模式下隐藏。
- **答题卡 / 反馈**：答对时显示「连对 X 次，X 天后见」，答错显示「明日再见」。（轻提示，不做成游戏化。）
- **会话结束页**：本次「升级 / 归零 / 毕业」的词数小结。
- **统计页**：新增掌握度分桶卡片（未学 / 学习中 / 已毕业 + 各级词数条形分布）。

两个模块（文言文 `/review`、`/stats` 与英语 `/english/review`、`/english/stats`）同构实现。

### 5.6 测试要点（`src/lib/srs/__tests__/srs.test.ts` 等）

- 重放推导：连对升级、答错归零、unknown 同 wrong、封顶毕业。
- `判我对` 覆盖后推导按 correct 计。
- dueAt 跨自然日边界（本地时区）。
- `due` 规则：到期封顶 30、新词补齐下限 10、无到期时纯新词、队列去重。
- 与 stats 现有口径不互相污染（SRS 只读日志，不改写）。

## 六、留给实现者的决定

- `srs.ts` 放 `src/lib/` 根还是各模块子目录：建议放根目录，接受 `wordId` 与日志表名参数，两模块传参复用。
- 掌握度分桶的图表形式：条形分布可用现有 recharts 或纯 CSS，实现者按现有统计页风格自选。
- 「今日到期 N」在设置页的刷新时机：进入页面拉取即可，不做轮询。
